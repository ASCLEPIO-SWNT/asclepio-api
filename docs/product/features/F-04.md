# F-04 — Sugerencia por LLM + SafetyGuards + fallback manual

**Objetivo:** proponer en segundos un nivel I–V con una explicación clínica trazable a los datos capturados, sin que nunca sea una decisión final.

**Usuarios:** `NURSE` (la solicita y la ve). El sistema la genera.

## Historias de usuario
- Como enfermería, quiero recibir una sugerencia de nivel con su justificación a partir de los datos capturados.
- Como enfermería, quiero que, si la IA no responde, pueda seguir con el triage manual sin esperar.
- Como dirección, quiero que cada sugerencia quede registrada con proveedor, modelo, versión del prompt y regla de seguridad aplicada.

## Criterios de aceptación globales
- **F-04.AC1** A partir de la captura clínica de una atención, el sistema genera una sugerencia con nivel 1–5, una explicación y los factores, que deben referirse a campos de la entrada.
- **F-04.AC2** El payload enviado al LLM no contiene nombre ni documento del paciente.
- **F-04.AC3** La respuesta del LLM se valida contra un esquema JSON. Si es inválida, la sugerencia queda con `status = INVALID_OUTPUT` y no se muestra un nivel.
- **F-04.AC4** Las llamadas usan `temperature = 0`, el modelo fijado por versión, timeout y un único reintento. Si Groq falla se usa OpenRouter; si ambos fallan, la sugerencia queda `TIMEOUT` o `FAILED` y la UI ofrece triage manual.
- **F-04.AC5** Los `SafetyGuards` deterministas se aplican después del LLM. **Solo pueden subir** la gravedad, y cuando actúan se guarda `guard_applied = true` con `guard_reasons`.
- **F-04.AC6** Cada intento guarda `input_snapshot`, `suggested_level`, `explanation`, `provider`, `model`, `prompt_version`, `raw_response`, `tokens_in`, `tokens_out`, `latency_ms` y `status`.
- **F-04.AC7** La sugerencia nunca cambia `final_level` ni el estado de la atención a `TRIAGED`.
- **F-04.AC8** La web muestra la sugerencia como **propuesta** (nivel, explicación, factores y aviso de guard), o el modo manual si no hay sugerencia válida.
- **F-04.AC9** Existe un conjunto de viñetas sintéticas (`ai/vignettes/`) y el comando `npm run ai:eval` para evaluar el prompt y el modelo cuando cambien.

## Dependencias
F-03.

## Fuera de alcance
Entrenar modelos propios, Random Forest, RAG, streaming de la respuesta y explicaciones en lenguaje para el paciente.

## Preguntas abiertas
- **PA-F04-1** **Reglas y umbrales exactos de los SafetyGuards**: por ejemplo, desde qué SatO₂, FC o PA se sube a qué nivel. Requiere asesor clínico; no se implementa ninguna regla sin umbral aprobado.
- **PA-F04-2** Modelo concreto (y su versión) en Groq y en OpenRouter.
- **PA-F04-3** Timeout por llamada y presupuesto total de latencia.
- **PA-F04-4** ¿La sugerencia se pide automáticamente al completar la captura o con un botón?
- **PA-F04-5** ¿Se permite volver a pedir una sugerencia si cambian los signos? ¿Cuál se muestra?
- **PA-F04-6** Número de viñetas y umbral mínimo de acierto o subclasificación para aceptar un cambio de prompt o modelo.
- **PA-F04-7** ¿El texto libre del motivo puede contener nombres? ¿Se debe sanear antes de enviarlo?
